WebGL, Mobile & 2D Games

Version 1.1 extends Photo Mode Pro beyond desktop 3D: captures work in WebGL builds, the UI is usable with touch, and orthographic (2D) games get a photo mode that behaves like one.

WebGL¶

On WebGL there is no user-visible file system, so captures are delivered two ways at once:

  • Browser download — every captured photo is handed to the browser as a regular file download the moment it is written. Tiled captures download too.
  • Persistent gallery — Unity's WebGL file system is backed by IndexedDB. Photo Mode Pro flushes it after every write, so the in-game gallery (and your saved looks) survive page reloads.

What changes compared to desktop:

  • The save folder row and the capture toast's reveal in file browser action are hidden — there is no file browser to open. Everything else, including render-layer EXR/PNG export and metadata sidecars, works the same (layer files stay in the gallery's storage rather than downloading individually).
  • Super-sample and tiled resolutions are limited by the browser's GPU memory; stay at or below 2× super-sampling for a typical WebGL build.

No setup is required — the platform is detected at runtime.

Mobile (touch)¶

The UI and camera are drivable entirely by touch:

  • One-finger drag on the viewport looks around (in 2D it pans instead).
  • Pinch zooms (FOV in 3D, orthographic zoom in 2D).
  • Two-finger drag pans the camera.
  • Panel controls (sliders, toggles, tabs) respond to taps as normal pointer input; hit targets grow slightly when a touch screen is the active pointer.

On narrow or portrait screens the hint-chip bar hides itself and the side panel clamps its width so the viewport stays usable. Touch input is additive: a connected gamepad or keyboard keeps working at the same time.

Android is verified in-engine and in the Android emulator. iOS is expected to work through the same touch path but is not yet a supported claim — it is on the roadmap.

2D / orthographic games¶

When photo mode opens on an orthographic camera it adapts automatically — there is nothing to configure:

  • Pan instead of fly. Move input pans the image plane; pan speed tracks the zoom level so framing feels consistent at any magnification. Look input is ignored (a flat scene has no depth axis to swing) and roll still works for dutch angles.
  • Zoom instead of FOV. The FOV slider relabels to Zoom and scales the camera's orthographic size proportionally — lower is tighter, matching the perspective slider's direction.
  • Orbit and the physical camera hide. Orbiting a flat scene only shows it edge-on, and focal length/aperture have no meaning without a projection, so both are hidden for the session.

Hiding 2D layers¶

Sorting layers cannot be culled with a camera mask, so Photo Mode Pro hides them by toggling renderers. List the sorting layer names you want the Hide 2D Layers toggle to affect in your PhotoModeSettings asset under Hidden Sorting Layer Names (for example a weather overlay or foreground parallax band). Every matching renderer's prior state is restored exactly on exit; if nothing in the scene matches, the toggle hides itself.

The package ships with a small 2D demo scene (PhotoMode2DDemo) built entirely from generated sprites.
