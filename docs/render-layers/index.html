Render Layers (AOV Export)

Beside every capture, Photo Mode Pro can export the render layers a compositor works with — depth, normals, albedo, object-ID mattes and alpha — as EXR and PNG files. Unity itself ships arbitrary output variables (AOVs) HDRP-only; Photo Mode Pro brings the layer set to URP and the Built-in pipeline through its own capture path, with per-pipeline capability gating and zero changes to your renderer assets.

The layers¶

Layer File Format Contents
Beauty photo.png PNG The normal graded capture.
Depth photo_depth.exr 32-bit float EXR Linear 0–1 view depth (1 = far plane).
Normals photo_normal.exr 16-bit half EXR World-space normals packed to 0–1, including material normal maps.
Albedo photo_albedo.png PNG Unlit base color exactly as authored.
Object IDs photo_id.png + photo_id_map.json PNG A distinct flat color per object, with a name→color sidecar.
Alpha photo_alpha.png PNG The clean-alpha coverage of the shot as grayscale.
Matte photo_matte.png PNG White-on-black selection matte by tag or layer mask (API / output presets).
Motion Vectors photo_motion.exr 16-bit half EXR HDRP only (Unity's AOV pass).

Files are named from the beauty capture plus a layer suffix, with the same collision-safe counter naming as photos. Unity's EXR encoder writes single-part files, so layers are per-pass files by design — the naming keeps them grouped.

Exporting¶

At runtime — Capture tab → Export Layers, then tick the layers you want. Unsupported layers on the active pipeline simply don't appear.

In the Capture Studio / shot lists — every output preset has a Layers mask (plus matte tag / layer-mask fields); "Render All" writes the layer set beside every shot in the matrix, headless runs included.

From script:

var controller = PhotoModeController.Instance;
controller.LayerExportMask =
    PhotoModeRenderLayerMask.Depth
    | PhotoModeRenderLayerMask.Normal
    | PhotoModeRenderLayerMask.ObjectId;
controller.MatteTag = "Player";      // optional Matte layer selection
controller.CapturePhoto();

PhotoModeController.ActiveLayerCapabilities reports what the active pipeline can produce.

In the compositor¶

The exported set is a standard multi-pass workflow — here is the classic routine in any node compositor (Nuke, Fusion, After Effects with plugins, Blender's compositor):

  1. Relight from Normals + Depth. Feed photo_normal.exr into a relight node (or compute dot(N, L) in an expression) to add a light that was never in the scene; use photo_depth.exr to attenuate it by distance.
  2. Depth-of-field in post. Drive a lens-blur node with photo_depth.exr as the focus map — pick focus after the shot, at any aperture, without re-rendering.
  3. Pull a matte from Object IDs. Keying the exact color listed in photo_id_map.json isolates one object; grade the subject and the background separately, or cut the subject onto a new backdrop with photo_alpha.png.
  4. Rebuild the grade from Albedo. photo_albedo.png is the texture color before lighting — divide the beauty by it for a lighting-only pass, or use it as an ID-independent base for restyling.

Per-pipeline notes¶

  • URP / Built-in — depth, normals, albedo, object IDs, alpha and mattes all ship. The capture path executes directly on the graphics device: no renderer feature is installed and your URP renderer asset is untouched (byte-identical, asserted by test).
  • HDRP — albedo, normals, depth and motion vectors go through Unity's own AOV pipeline; object IDs and mattes use the shared capture path. Alpha is gated (HDRP has no clean-alpha capture, matching transparent capture).
  • Albedo and normals read the standard material properties (_MainTex / _BaseMap, _BumpMap); heavily custom shaders fall back to white albedo / geometric normals for those objects.
