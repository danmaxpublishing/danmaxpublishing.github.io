Tiled Capture (Beyond the GPU Limit)

GPUs cap single textures around 16K; Photo Mode Pro renders past that by splitting the frame into a grid of frustum-offset tiles and streaming them straight into the PNG on disk — 32,768 × 32,768 and beyond on commodity hardware, with peak memory bounded by one tile row, not the image.

Other capture assets are supersampling wrappers capped by what the GPU can allocate in one texture. The one true tiler on GitHub is an Editor-only Unity Recorder plugin — and it does not solve post-processing across tile seams, which is the actually hard part. Photo Mode Pro does; the rules below are the engineering.

Using it¶

  • Runtime — Capture tab → the TILED row: 8K (7680×4320), 16K (15360×8640) or 32K (30720×17280). The processing badge shows while the grid renders; wall time, tile count and measured peak memory are logged.
  • Capture Studio / shot lists — tick Tiled on an output preset (or just set dimensions beyond the GPU limit; the studio routes automatically). Tiled outputs stream to PNG — EXR needs the whole frame in memory, so the combination is reported rather than silently degraded.
  • Script — PhotoModeTiledCapture.Capture(camera, adjustments, backend, width, height, directory, fileName) returns the path, tile count, wall time and measured peak memory.

The seam rules¶

Screen-space post-processing is wrong at naive tile boundaries: a vignette evaluated per tile darkens every tile's edges; grain restarts its noise field at every seam; a depth-of-field kernel at a tile border blurs against nothing. Photo Mode Pro applies one rule per effect class:

  1. Full-frame-UV effects (vignette, grain) are taken out of the pipeline during tile renders and re-evaluated against full-frame coordinates in a per-tile overlay pass — the falloff and the noise field are continuous across seams by construction. The vignette uses the same falloff as the pipeline's; grain uses the package's own full-frame noise field, so its character differs marginally from the pipeline's texture-based grain. The overlay also applies the vignette after tonemapping rather than before it as the pipeline does, so with Neutral or ACES tonemapping a tiled export's vignette reads slightly flatter than the preview's.
  2. Depth of field renders with an overlap margin (64 px) that is cropped away — the blur kernel sees real context past the seam instead of blurring against nothing.
  3. Effects that cannot be made seam-correct are disabled for tiled output rather than rendered wrong: bloom, chromatic aberration, lens distortion and motion blur are turned off during the tile renders (a bloom halo or a distortion warp evaluated per tile would repeat at every seam). The presenter-pass extras — sharpen, tilt-shift, the HSL qualifier — and LUT filters are likewise not applied to tiled output. All of these still appear in normal (non-tiled) captures.

A regression test renders a tiled capture with strong vignette and grain and asserts pixel continuity across every seam, and a tiled 4×4 render is asserted to match a single-pass render of the same resolution within tolerance.

Notes¶

  • Output is 8-bit RGBA PNG, written by the package's own scanline-streaming encoder (pure Unity/BCL — no third-party code) so the full image never exists in memory.
  • The transparent-background option on output presets does not apply to tiled captures; tiled output is always fully opaque.
  • Rendering pauses the game thread for the duration; a 32K capture takes on the order of a minute depending on scene and disk.
  • Motion-dependent effects (temporal AA) are not part of tile renders.
